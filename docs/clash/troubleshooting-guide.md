## 故障一：节点测速全部显示“超时 (Timeout)”或全红，一个都连不上

### 典型症状
在节点列表里点击测速小飞机，所有国家和节点全部显示 `Timeout`（超时）或红色的 `N/A`，即使切换策略也无法访问任何外网。

### 🔍 根本原因与排查步骤
1. **【最常见隐形元凶】：系统时间与国际标准时间不同步（偏差超过 60 秒）**
   - **原理**：所有现代加密协议（Trojan、Shadowsocks-2022、Vless、TLS 1.3）都极其依赖时间戳校验。一旦你的电脑或手机系统时间比标准互联网时间慢了或快了 **超过 60 秒**，服务器会判定握手报文为重放攻击，**直接暴力丢弃数据包，导致全节点超时！**
   - **秒级修复**：
     - **Windows**：打开「系统设置」→「时间和语言」→「日期和时间」，点击**「立即同步 (Sync now)」**按钮；
     - **macOS**：打开「系统设置」→「通用」→「日期与时间」，确保开启“自动设置时间”；
     - 同步成功后，回到客户端重新测速，节点瞬间恢复绿色！
2. **本地防火墙或安全软件拦截了内核**
   - 检查 360 安全卫士、火绒或 Windows Defender 是否在更新后误把 `mihomo.exe` 当作未知威胁拦截了外网出站权限。在防火墙允许列表中放行客户端即可。

## 故障二：关掉 Clash 后，电脑彻底断网，连国内百度、微信都打不开了

### 典型症状
关闭了 Clash 客户端，或者电脑意外重启后，打开浏览器提示：`代理服务器未响应 (ERR_PROXY_CONNECTION_FAILED)`，国内所有网站打不开，微信也显示转圈圈。

### 🔍 根本原因与修复方法
- **原因**：客户端在异常退出（如任务管理器强制结束、电脑死机蓝屏、未关闭“系统代理”就直接叉掉软件）时，**没有来得及恢复操作系统的代理注册表设置**。系统依然傻傻地把所有流量发往已经不存在的 `127.0.0.1:7890` 端口。
- **秒级修复（Windows）**：
  1. 按快捷键 `Win + I` 打开系统设置；
  2. 点击「网络和 Internet」→「代理」；
  3. 找到**「手动设置代理 (Use a proxy server)」**，将其**完全关闭（切换为关/Off）**！
  4. 刷新网页，电脑网络立即满血复活！
- **优雅预防**：日常退出客户端时，建议先在客户端主界面**关闭「系统代理」开关**，再右键托盘彻底退出软件。

## 故障三：导入或更新订阅时，提示“Download Failed (403 / 500 / Network Error)”

### 典型症状
在客户端里粘贴机场订阅链接，点击保存或更新时，弹窗报红显示 `Invalid URL` 或 `Status code: 403 / 500`。

### 🔍 根本原因与解决方案
1. **订阅链接被输入法插入了空格或特殊字符**
   - 检查复制的长链接前后，是否夹带了无形的换行符或空格，清除后再试。
2. **机场防爬虫机制拦截了默认 User-Agent (UA)**
   - 许多机场为了防止黑客扫描，只允许特定客户端 UA 拉取订阅。
   - **修复办法**：在客户端的订阅高级设置中，将 **User-Agent** 手动修改为 `clash.meta` 或 `ClashVerge`，然后重新保存拉取。
3. **订阅转换服务节点波动**
   - 尝试在无代理环境下直连拉取，或者打开全局代理后再拉取订阅。

## 故障四：浏览器能正常翻墙，但微软商店 (Microsoft Store) 与 UWP 应用打不开

### 典型症状
Chrome 访问外网飞快，但 Windows 自带的微软应用商店、Xbox 游戏应用、OneDrive 同步盘提示无法连接网络。

### 🔍 根本原因与解决方案
- **原因**：Windows 系统对 UWP 应用采用了**本地网络沙盒隔离机制（Loopback Isolation）**，默认禁止 UWP 应用向本地主机地址（`127.0.0.1:7890`）发起回环网络请求。
- **秒级修复**：
  - 在 Clash Verge Rev 或其他客户端内，找到并打开 **「UWP 应用回环解除工具 (Enable Loopback Utility)」**；
  - 点击「Exempt All（全部豁免）」并保存，UWP 应用即可正常通过代理联网。

## 故障五：端口冲突，启动报错“Listen on mixed-port 7890 failed”

### 典型症状
打开客户端时，右下角弹窗报错：`Listen tcp 127.0.0.1:7890: bind: address already in use`，无法开启代理服务。

### 🔍 根本原因与解决方案
- **原因**：`7890` 端口被其他旧版代理软件（如之前的 v2rayN、旧版 CFW、抓包工具 Fiddler）长期占用，或者上一个后台残留的 Clash 进程尚未完全结束。
- **秒级修复**：
  - 在客户端「设置」中，将 **混合端口（Mixed Port）** 从 `7890` 手动更改为一个冷门端口（例如 `7892` 或 `17890`），保存并重启内核即可妥善解决。

## 故障六：外服游戏、Git 终端、Docker 依然无法翻墙

### 典型症状
网页打开外网流畅，但终端 `git clone` 或游戏依然报连接超时。

### 🔍 根本原因与解决方案
- **原因**：当前仅开启了普通「系统代理」，并未开启「TUN 虚拟网卡模式」。
- **秒级修复**：以管理员身份运行客户端，安装服务模式并**开启「TUN 模式」**。
- 👉 **详细深度解读**：请参阅本站 [**TUN 模式深度解析专文**](/clash/tun-mode-explained)。
